# 02 · 邮件与消息

> 最后验证：2026-11-03 ｜ 适用：Grok Bot、Dots ｜ 国内可用性：待作者实测 ｜ 状态：初稿

收件箱和工作群最消耗人的地方，不是回复，而是"每条都得点开看一眼才知道要不要管"。**这个场景要做的，是让 Agent 先替你读完，只把少数几条必须你处理的报上来，回复先写成草稿，等你点头再发。**

**典型任务**：收件箱分拣、工作群和私信分拣、起草回复

| | 怎么用 |
|---|---|
| 🧑‍💼 管理者 | 只看必须亲自处理的几条，其余的它起草、你确认 |
| 🧑‍💻 执行者 | 不漏掉同事和客户的请求，回复更快 |

**推荐产品**：Grok Bot（能按时自己跑，草稿等你确认再发）｜备选：Dots

> [!IMPORTANT]
> 本节 3 条 tips 都来自同一位 Grok Bot 团队成员的分享[^s02-josh]，**利益相关：产品方**。这是"官方怎么用"的示范，不等于第三方评测；第三方案例收集中。

## Tips

1. **只上报约 3 条重要又紧急的。** 收件箱 Bot 的价值不在读完所有邮件，而在替你决定哪些不用看。[^s02-josh]
2. **草稿有上限，发送靠一个词。** 最多起草 5 条回复，你回复"send"才发出。规则越简单，越不会误会。[^s02-josh]
3. **错开整点运行。** 例如工作日 9:05 和 16:05 各跑一次，避开会议高峰。[^s02-josh]

## 一键复制

以下提示词均为作者原创，CC0，可直接复制、修改。把【】里的内容换成你自己的。②的节奏和上限参考 [^s02-josh]，不是原帖提示词。

| 你的情况 | 用哪条 |
|---|---|
| 第一次试，想 1 分钟上手 | ① 极简版 |
| 邮件多，想每天只看几条 | ② 收件箱分拣（管理者） |
| 消息主要在工作群和私信里 | ③ 工作群和私信分拣（执行者） |
| 手上有一封难回的邮件 | ④ 起草一封回复：给我三个版本 |
| 休假回来，积压了几百封 | ⑤ 一次性清积压 |
| 发出去的邮件常常石沉大海 | ⑥ 没回音的邮件提醒我跟进 |
| 不知道该怎么定规则 | ⑦ 先问我，再帮我配置 |

**① 极简版**

```
每个工作日 9:05，读一遍我昨天以来的邮件，只告诉我最多 3 封必须我亲自处理的，每封 1 句话说明原因。不要替我回复或删除任何邮件。
```

**② 收件箱分拣（管理者）**

```
你是我的收件箱助理。每个工作日 9:05 和 16:05 各运行一次：
1. 读完上次运行以来的所有邮件和私信
2. 只上报最多 3 条"又重要又紧急、必须我亲自处理"的，每条 1 句摘要 + 为什么必须是我
3. 能代我回复的，最多起草 5 条回复，附在后面
4. 其余的按"可以晚点看 / 不用看"两类，各列一行标题即可
规则：
- 我回复"send"，你才发出对应草稿；没有这个词，一律不发
- 不删除、不归档任何邮件
- 拿不准该不该上报的，宁可上报，并标【待确认】
```

<summary><b>③ 工作群和私信分拣（执行者）</b></summary>

```
每个工作日 9:05 和 16:05，帮我过一遍【工作群名称】和私信：
1. 列出所有"有人在等我回复或交付"的消息：谁、要什么、什么时候要
2. 按截止时间排序；没写截止时间的标【未说明】
3. 每条起草一句回复，等我确认后再发
不用汇报闲聊和与我无关的讨论。
```

</details>

<details>
<summary><b>④ 起草一封回复：给我三个版本</b></summary>

```
帮我回复这封邮件：【粘贴邮件或说明是哪一封】
我的意思是：【一两句话说清你想表达什么，例如"这周做不了，下周三可以"】
给我三个版本，各不超过 120 字：
A. 简短直接
B. 礼貌委婉
C. 更正式，适合发给【客户 / 上级】
口吻参考我以前写的这几封：【粘贴 1–3 封你写过的回复】
只起草，不要发送。
```

</details>

<details>
<summary><b>⑤ 一次性清积压</b></summary>

```
我【休假 / 出差】回来，收件箱里积压了很多邮件。帮我一次性过一遍【日期】以来的邮件，分成四类：
1. 必须我亲自处理：每封 1 句摘要 + 截止时间，按紧急程度排序
2. 需要回复但可以你起草：列标题，各附一份草稿
3. 只需知道：合成一段不超过 200 字的摘要
4. 不用看：只给数量
规则：只读和起草，不删除、不归档、不发送。
```

</details>

<details>
<summary><b>⑥ 没回音的邮件提醒我跟进</b></summary>

```
每个工作日 16:05，检查我发出的邮件：
- 找出发出超过【3】天、对方还没回复、而且在等对方答复的邮件
- 每封写 1 句：发给谁、在等什么
- 各起草一封简短的跟进邮件，语气友好，不催促
我回复"send + 编号"才发出对应的跟进邮件。
```

</details>

<details>
<summary><b>⑦ 先问我，再帮我配置</b></summary>

```
我想让你每天帮我分拣邮件和消息，但还没想清楚规则。
先问我 5 个问题，弄清楚：哪些人的邮件一定要上报、哪些可以你起草回复、哪些可以忽略、我希望几点收到汇报、发送前怎么确认。
问完后，帮我写一份分拣规则，给我确认；我说"可以"之后再排进定时任务。
```

</details>

**口吻样本**（作者建议）：不管用哪条，第一次用之前附上 3 封你自己写过的回复，再加一句"按这几封的口吻起草"。

## 要设置的审批点

- **发送**：一律等你说"send"。这一条不要放开，至少跑满四周再考虑（见 [00 · 把 Agent 引入工作](../README.md#00--把-agent-引入工作)的四周节奏）
- **删除、归档、退订**：都不交给它
- **代你答应时间、价格、承诺**：只能写进草稿，由你确认

## 翻车提醒

- **它判断"不用看"的，也要抽查。** 第一周让它把跳过的邮件也列一份标题清单，确认没有漏掉重要的再放手。（作者建议）
- **接了邮箱，等于同账号下的其他 Bot 也能用这份登录。** Grok Bot 同一用户的 Bot 共用一台电脑和全部登录，不是权限边界[^s02-codepick]；敏感邮箱宁可不接。
- **先少接。** 有的产品撤销授权后数据可能仍被保留[^s02-noma]，可以先接一个专用邮箱试跑，再接主邮箱。
- **国内办公软件能不能接，待实测。** 主流产品官方集成的多是 Slack 和 Teams；飞书、钉钉、企业微信需要实测。（待作者实测）
